## 2. 五维评分卡：通顺度

### 2.1 评分总则

| 分值 | 含义 | 判定标准 |
|------|------|---------|
| **2 分** | 规范/自然 | 该维度无任何可感知问题，符合标准书面语习惯 |
| **1 分** | 可接受但可优化 | 有轻微不自然但不影响理解，或存在低频搭配但语感可接受 |
| **0 分** | 存在硬伤 | 明显语法错误、成分残缺、搭配不当，影响阅读理解 |

**关键判据**：**0 分是硬伤，必须修复；1 分是提升空间，视总分决定是否报。**

### 2.2 维度①：成分完整

> 判断主语、谓语、宾语是否完整，是否存在残缺或叠床架屋。

| 分值 | 判定 | 例句 | 说明 |
|------|------|------|------|
| **2** | 成分完整 | `公司决定扩大生产规模。` | 主谓宾齐全，修饰语位置正确 |
| **1** | 略松散但不缺 | `对于公司的这个决定，我们表示支持。` | 介词短语前置，主语后置，稍显松散但成分完整 |
| **0** | 成分残缺 | `通过这次会议，使得大家明确了方向。` | "通过…使得"双重介词导致主语缺失 |
| **0** | 成分残缺 | `由于成本上升，导致了利润下降。` | "由于…导致"使句子缺少独立主语 |
| **0** | 双主语 | `这个问题，我们需要认真对待它。` | "这个问题"和"它"构成双主语 |
| **0** | 缺宾语 | `公司制定了并实施了。` | "制定了"缺少宾语 |

**正则可检测模式（Layer 1）**：
- `通过(.*?)(使|让|令)` — 缺主语型句式杂糅 → `metric: fluency`
- ~~`由于(.*?)(导致|造成|使得)`~~ — 保留给 LLM（"由于成本上升导致利润下降"有时可接受）

**LLM 检测策略（Layer 2）**：
- 扫描句首介词链（"在…下/通过…/对于…/由于…"），检查后续是否有独立主语
- 检查动词是否有必要宾语
- 识别"被…所…"等双标记结构

### 2.3 维度②：搭配得当

> 判断动宾搭配、定中搭配、主谓搭配是否符合汉语习惯。

| 分值 | 判定 | 例句 | 说明 |
|------|------|------|------|
| **2** | 搭配规范 | `企业应履行社会责任。` | 动宾搭配符合习惯 |
| **1** | 搭配生僻但不误 | `强化了对风险的管理力度。` | "强化…力度"可接受但不精简 |
| **0** | 动宾搭配不当 | `我们应该履行这些作用。` | "作用"不可"履行"，应为"发挥…作用" |
| **0** | 定中搭配不当 | `这是一个严重的贡献。` | "严重"不可修饰"贡献" |
| **0** | 主谓搭配不当 | `产品的质量发生了飞跃。` | "质量"不能"发生飞跃"，应为"实现了飞跃" |
| **0** | 介词搭配错误 | `根据于调查结果，…` | "根据于"不存在，应为"根据" |

**正则可检测模式（Layer 1）**：
- 暂无高确定性规则（搭配判断高度依赖语境，正则误报率高）

**LLM 检测策略（Layer 2）**：
- 基于共现统计：检查高频动宾搭配、定中搭配
- 特别关注："履行+作用""达成+目的""实现+结果""取得+成绩"等
- 区分"正式搭配"与"口语搭配"（如"搞好关系"在正式公文中标记为1分）

### 2.4 维度③：语序自然

> 判断修饰语位置、否定词位置、状语位置是否符合汉语语序习惯。

| 分值 | 判定 | 例句 | 说明 |
|------|------|------|------|
| **2** | 语序自然 | `我们已按合同要求完成了所有工作。` | 状语位置正确 |
| **1** | 稍显欧化但可接受 | `我们完成了所有工作，按照合同的要求。` | 状语后置，口语中常见 |
| **0** | 语序错乱 | `我把作业没有做完。` | 否定词位置错误，应为"没有把作业做完" |
| **0** | 状语错位 | `他工作地在上海。` | 应为"他在上海工作" |
| **0** | 多重定语混乱 | `这是一家上海的致力于环保的科技创新公司。` | 多重定语堆砌，语序混乱 |
| **0** | 补语错位 | `他比我跑得快三分钟。` | 应为"他比我快三分钟"或"他跑得比我快三分钟" |

**正则可检测模式（Layer 1）**：
- 暂无高确定性规则（语序判断需要句法分析）

**LLM 检测策略（Layer 2）**：
- 状语位置：时间状语→地点状语→方式状语 的标准语序校验
- 否定词位置：`把字句`（否定词在"把"之前）、`被字句`（否定词在"被"之前）
- 多重定语排序：领属→时间地点→数量→动词性→形容词性→名词性

### 2.5 维度④：句式干净

> 判断是否存在句式杂糅、欧化长句、滥用被动、冗余框架。

| 分值 | 判定 | 例句 | 说明 |
|------|------|------|------|
| **2** | 句式干净 | `调查显示，用户满意度达到95%。` | 单一句式，表达直接 |
| **1** | 轻微冗余 | `需要指出的是，数据还存在一些误差。` | "需要指出的是"是框架废话但可容忍 |
| **0** | 句式杂糅 | `根据调查显示，用户满意度很高。` | "根据调查"+"调查显示"杂糅，选其一 |
| **0** | 句式杂糅 | `原因是由于管理不善造成的。` | "原因是"+"由于"+"造成的"三重杂糅 |
| **0** | 滥用长被动 | `该方案被经过多轮讨论后被认为是可以接受的。` | 多重被动嵌套 |
| **0** | 欧化长句 | `这是一个当我们在考虑方案的时候必须要面对的问题。` | 多层从句堆砌 |

**正则可检测模式（Layer 1）**：

| # | 正则 | 类型 | metric | 示例 |
|---|------|------|--------|------|
| 1 | `通过(.*?)(使\|让\|令)` | `句式杂糅` | `fluency` | "通过这次会议，**使**大家明确了方向" |
| 2 | `根据(.*?)显示` | `句式杂糅` | `fluency` | "**根据**调查**显示**" |

**⚠️ 正则捕获范围要求**：`original` 必须完整捕获整个冗余短语。例如规则1的 `original` 宜为 `"通过这次会议，使"` 而不是只捕获 `"使"` — 确保 P16 子串校验兼容。

**LLM 检测策略（Layer 2）**：
- 检测 `根据(.*?)认为/指出/显示`、`原因是(.*?)由于/因为/造成的` 等杂糅模式
- 识别"对于…而言""从…角度来看""在…背景下"等欧化框架
- 检测"被…所…""被…给…"等双被动标记
- "众所周知""需要注意的是""可以说""毫无疑问" → 标记为 1 分（冗余但不杂糅）

### 2.6 维度⑤：衔接连贯

> 判断关联词配对、指代清晰度、句间逻辑连贯性。

| 分值 | 判定 | 例句 | 说明 |
|------|------|------|------|
| **2** | 衔接连贯 | `由于成本上升，公司决定提价。然而，市场对此反应消极。` | 关联词匹配，指代清晰 |
| **1** | 衔接略弱 | `成本上升了。公司决定提价。反应消极。` | 无关联词，逻辑靠读者推断 |
| **0** | 关联词失配 | `虽然成本上升，但是公司决定提价。` | "虽然…但是"表示转折，但两句之间是因果关系，应为"因为…所以" |
| **0** | 指代不明 | `小明和小红去公园，他带了伞。` | "他"指代不明 |
| **0** | 关联词残缺 | `一方面成本在上升，公司需要提价。` | "一方面"缺少配对"另一方面" |
| **0** | 句间逻辑断裂 | `项目取得了成功。因此我们决定放弃。` | "成功"与"放弃"逻辑矛盾 |

**正则可检测模式（Layer 1）**：
- 暂无高确定性规则（衔接判断跨句，正则无法处理）

**LLM 检测策略（Layer 2）**：
- 关联词配对准：虽然→但是、因为→所以、不但→而且、一方面→另一方面
- 指代消解：检查代词（他/她/它/其/该）的先行词是否唯一且明确
- 逻辑一致性：检查关联词表达的转折/因果/递进是否与句子实际语义一致

### 2.7 评分示例

**示例 1：高分行（8-10 分）**

> `公司经过审慎研究，决定自下月起调整产品价格。该决定已获董事会批准，将在内部公告后正式执行。`

| 维度 | 评分 | 理由 |
|------|------|------|
| ① 成分完整 | 2 | 主谓宾齐全，无残缺 |
| ② 搭配得当 | 2 | "审慎研究""调整价格""获董事会批准"搭配规范 |
| ③ 语序自然 | 2 | 状语"经审慎研究"前置符合汉语习惯 |
| ④ 句式干净 | 2 | 无杂糅、无欧化 |
| ⑤ 衔接连贯 | 2 | "该决定"指代清晰，"将在"衔接自然 |
| **总分** | **10/10** | ✅ 通顺，不报 |

**示例 2：中间分（6-8 分）**

> `需要指出的是，根据我们对市场的调查显示，由于成本上升的原因，使得利润出现了下降的趋势。`

| 维度 | 评分 | 理由 |
|------|------|------|
| ① 成分完整 | 1 | "使得"前缺主语，但语义可补全 |
| ② 搭配得当 | 2 | 动宾搭配无问题 |
| ③ 语序自然 | 1 | 句首介词链过长 |
| ④ 句式干净 | 0 | **"根据…显示"杂糅 + "由于…的原因"冗余** |
| ⑤ 衔接连贯 | 2 | 句子间无断裂 |
| **总分** | **6/10** | ⚠️ 单维 0 分（④），触发修复 |

**示例 3：低分（<6 分）**

> `我把作业没有做完，因为昨天晚上的时候，我的电脑被死机了，导致于我无法继续做。`

| 维度 | 评分 | 理由 |
|------|------|------|
| ① 成分完整 | 1 | 成分完整但松散 |
| ② 搭配得当 | 0 | **"被死机"搭配不当**（死机是不及物动词） |
| ③ 语序自然 | 0 | **"我把作业没有做完"否定词错位** |
| ④ 句式干净 | 0 | **"的时候"冗余 + "导致于我"杂糅** |
| ⑤ 衔接连贯 | 1 | "因为"引导的原因从句后置，口语化 |
| **总分** | **2/10** | ❌ 不通顺，3 个单维 0 分，触发全面修复 |

## 3. 最小化测试：简洁度

### 3.1 算法定义

```
简洁度 = 1 - (可删除字数 / 句子总字数)

可删除字数 = Σ(语义不变的可删除片段字数)

判定器：对候选冗余片段 {删除后→原句→LLM 自检"语义是否完全不变？"}
```

### 3.2 冗余成分分类（4 类）

#### 类型 1：同义反复（确定性高，部分可正则）

| 冗余词组 | 建议 | metric |
|---------|------|--------|
| 大约…左右 | 删"左右"或"大约" | conciseness |
| 目的是为了 | 删"目的"或"为了" → "是为了" | conciseness |
| 首次开创 | 删"首次" → "开创" | conciseness |
| 亲眼目睹 | 删"亲眼" → "目睹" | conciseness |
| 更加进一步 | 删"更加" → "进一步" | conciseness |
| 属于…之一 | 删"之一" → "属于" | conciseness |
| 涉及到 | 删"到" → "涉及" | conciseness |

> **注意**：现有 Layer 1 规则已覆盖部分（如"涉及到""原因是由于"），本次新增的 5 条简洁规则不与之重复。

#### 类型 2：空洞填充词（确定性高，正则可覆盖）

| 冗余词 | 示例 | 修复 | metric |
|--------|------|------|--------|
| 进行 | `进行研究` → `研究` | 删"进行" | conciseness |
| 作出 | `作出决定` → `决定` | 删"作出" | conciseness |
| 予以 | `予以解决` → `解决` | 删"予以" | conciseness |
| 加以 | `加以完善` → `完善` | 删"加以" | conciseness |

**Layer 1 新增 4 条正则规则（#21 实施）**：

| # | 正则 | original 示例 | metric | type |
|---|------|-------------|--------|------|
| 3 | `进行(了)?(研究\|分析\|讨论\|处理\|调查)` | "进行研究" | conciseness | 冗余词 |
| 4 | `作出(了)?(决定\|部署\|安排)` | "作出部署" | conciseness | 冗余词 |
| 5 | `予以(了)?(解决\|处理\|落实)` | "予以落实" | conciseness | 冗余词 |
| 6 | `加以(了)?(解决\|完善\|规范)` | "加以规范" | conciseness | 冗余词 |

> **⚠️ 语境敏感度**：上述 4 条规则在以下场景中可能误报——法律文书（"作出如下决定"）、学术论文（"对数据进行了统计分析"）、正式公文（"现予以批复"）。因此这些规则的 `getSuggestion` 应生成建议性措辞（如"建议替换为'研究'，请复核语境"），而非断言式"自动删除"。Layer 1 保留正则检测的高召回率，Layer 2（P16 confirm 阶段）可利用完整上下文判定是否实际执行修复。

#### 类型 3：框架废话（确定性中，LLM 判定）

| 框架废话 | 说明 | metric |
|---------|------|--------|
| 我们需要注意的是 | 可删，直接说内容 | conciseness |
| 众所周知 | 可删，或保留（视语境） | conciseness |
| 可以说 | 可删 | conciseness |
| 需要指出的是 | 可删 | conciseness |
| 毫无疑问 | 可删 | conciseness |
| 针对…这一问题 | 可压缩为直接陈述 | conciseness |

**Layer 1 新增 1 条正则（#21 实施）**：

| # | 正则 | 示例 | metric | type |
|---|------|------|--------|------|
| 7 | `针对(.*?)这一问题` | "针对效率低下这一问题" | conciseness | 冗余词 |

#### 类型 4：可压缩从句（确定性低，LLM 判定）

| 冗余从句 | 修复 | metric |
|---------|------|--------|
| 在这个时代背景下 | 删或降级为"当前" | conciseness |
| 从某种意义上来说 | 删 | conciseness |
| 在某种程度上 | 删 | conciseness |
| 就目前而言 | 删或改为"目前" | conciseness |

> **归属**：类型 3 的第 7 条正则 + 类型 4 的全部留给 LLM 语境判断。

### 3.3 判定与修复规则

| 冗余占比 | 判定 | 动作 |
|----------|------|------|
| ≥ 25% | 啰嗦 | **触发修复**（出 issue + 建议） |
| 10% – 25% | 可精简 | **仅报告不修**（入"优化建议"小节） |
| < 10% | 简洁 | 不报 |

**执行期约束（铁律，须写进 SKILL.md）**：
1. **通顺 > 简洁**：任何简洁修复必须：① 通过"删除后语义不变"自检；② 修复后不得触发新的通顺 issue
2. 若简洁修复可能导致通顺度下降，即使冗余占比 ≥25%，也**只报告不修**，除非 LLM 能给出同时保持通顺的替代表述
3. 修复建议至少提供 2 个选项（保守/激进），用户可择其一
4. **简洁修复尝试最多 1 轮**（1 次修复 + 1 次通顺自检），若不通过则放弃修复，将该问题降级为「优化建议」并标注原因：`简洁修复可能影响通顺，建议人工处理`

## 5. Layer 1 → Layer 2 数据流

### 5.1 完整数据流

```
Step 1: Layer 1 执行（已扩展 metric 输出）
  proofreadBasic(text, startOffset) → {
    issues: [
      { offset, original, type: "句式杂糅", metric: "fluency", ... },
      { offset, original, type: "冗余词", metric: "conciseness", ... },
      ...
    ]
  }

Step 2: Layer 2 执行（新五维评分卡 + 最小化测试）
  AI 分析本批文本，逐句执行：
    2a. 五维评分 → 每句 { total, dimensions }
    2b. 若 total < 6 或 存在单维 0 → 出 issue（metric: fluency, score）
    2c. 若 total 6-8 且无 0 分 → 只报告（带分数），不出 issue
    2d. 最小化测试 → 计算冗余占比
    2e. 若冗余占比 ≥25% → 出 issue（metric: conciseness, redundancy_ratio）
    2f. 若冗余占比 10-25% → 只报告（带占比），不出 issue
  → issues: [{ ..., metric, score/redundancy_ratio }]

Step 3: confirmBatchAiProofread（不变）

Step 4: 合并去重
  - offset+original 去重
  - Layer 2 命中同一问题 → 保留 Layer 2 的（含 score 等元数据）
  - 统计按 metric 分组

Step 5: 修复
  - 常规修复：已匹配已知 issue → P16 自动放行
  - 语义性发现未匹配 Layer 1 issue → 走 _force_ai_fix 通道（附评分卡证据）
  - 6-8 分 + 10-25% 冗余 → 不进入修复，只进入报告
```

### 5.2 P16 兼容性分析

```
场景 A：正则规则命中（Layer 1 的 issue）
  → original 被 P16 收录
  → AI 修复时 findText 与 original 子串匹配
  → P16 自动放行 ✅

场景 B：LLM 发现但正则未命中（语义级问题）
  → 不在 P16 的 proofreadIssueOriginals 中
  → AI 修复需要 _force_ai_fix: true
  → 且 SKILL.md 明示：必须附评分卡证据（score < 6 或 单维 0）

场景 C：简洁修复
  → 若 Layer 1 未覆盖（类型 4 从句压缩等）
  → 同场景 B，走 _force_ai_fix
  → 额外要求：通顺 > 简洁自检通过
```

## 9. 实现细节

以下内容由全栈开发工程师在 PR #40 中实现。更多实现细节见代码文件 `wps-office-mcp/src/tools/word/proofread-report.ts`。

### 9.1 维度合并说明

**`standardization`（规范性）维度在 Layer 1 实现中合并入 `consistency`（一致性）**。

原因：Layer 1 正则规则检测到的"规范性问题"（中英混排、数字空格、中文标点、用词统一、异常空格）本质上属于格式一致性问题——规范即一致性。合并后 `consistency` 维度涵盖了所有格式层面的问题。

AI Layer 2 中 `standardization` 仍可独立存在，用于检测更复杂的规范性语义问题（如措辞风格、行业规范等）。

**`completeness`（完整度）为 Layer 1 新增维度**。

原因：占位文本检测（如 "xxx有限公司"、"TODO"）是一个独立于其他四个维度的概念——它不涉及语言质量，而是内容完整性。占位文本属于 blocker 级问题（有则得 0 分）。

### 9.2 评分量表与归一化

**Layer 1 原始分**：1-5 量表（`METRIC_WEIGHT_FORMULA` 公式计算，completeness 可能为 0）

**Layer 2 AI 评分卡**：0/1/2 三级制

**归一化路径**：

```
Layer 1: rawScore (1-5) → normalizeToTwoPointScale → [0, 2]
Layer 2: 0/1/2 (直接)

综合分: min(L1_norm, L2) × 5 → X.X/10
```

归一化公式：`normalized = max(0, min(2, (rawScore - 1) / 2))`

| rawScore | normalized | display |
|----------|-----------|---------|
| 5.0     | 2.00      | 10.0/10 |
| 4.0     | 1.50      | 7.5/10  |
| 3.0     | 1.00      | 5.0/10  |
| 2.0     | 0.50      | 2.5/10  |
| 1.0     | 0.00      | 0.0/10  |
| 0.0     | 0.00      | 0.0/10  |

### 9.3 TYPE_METRIC_MAP

完整映射表见 `wps-office-mcp/src/tools/word/proofread-report.ts` 中的 `TYPE_METRIC_MAP`。

### 9.4 权重公式

```typescript
const METRIC_WEIGHT_FORMULA = {
  fluency:       (c) => Math.max(0, 5 - c * 0.2),
  conciseness:   (c) => Math.max(0, 5 - c * 0.3),
  accuracy:      (c) => Math.max(0, 5 - c * 1.0),
  consistency:   (c) => Math.max(0, 5 - c * 0.1),
  completeness:  (_c, hasPlaceholder) => hasPlaceholder ? 0 : 5,
};
```

| 维度 | 权重 | 下限 |
|------|------|------|
| fluency（流畅度） | 5 - count×0.2 | 0 |
| conciseness（简洁度） | 5 - count×0.3 | 0 |
| accuracy（准确性） | 5 - count×1.0 | 0 |
| consistency（一致性） | 5 - count×0.1 | 0 |
| completeness（完整度） | hasPlaceholder?0:5 | 0 |

## 通顺度五维评分卡（逐句评分）

对当前句子从以下 5 个维度各打 0/1/2 分：

| 维度 | 0 分（硬伤） | 1 分（可优化） | 2 分（规范） |
|------|-------------|---------------|-------------|
| 成分完整 | 缺主语/缺宾语/双主语 | 介词短语前置但成分全 | 主谓宾齐全 |
| 搭配得当 | 动宾不当/主谓不当 | 搭配生僻但可接受 | 搭配规范 |
| 语序自然 | 否定词错位/状语错位 | 稍欧化但可接受 | 语序自然 |
| 句式干净 | 句式杂糅/滥用被动 | 含框架废话 | 句式干净 |
| 衔接连贯 | 关联词失配/指代不明 | 无关联词但可推断 | 衔接自然 |

判定规则：
- 总分 ≥8 且无 0 分 → 通顺，不出 issue
- 总分 6-8 且无 0 分 → 只报告分数（优化建议），不出 issue
- 总分 <6 或 存在 0 分 → 出 issue，附 score 对象

- 逐片段执行最小化测试（删除 → 语义是否不变）
- 冗余占比 ≥ 25% → 出 issue（metric: conciseness）
- 冗余占比 10-25% → 只报告占比（优化建议），不出 issue
