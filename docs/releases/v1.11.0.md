## 一、本次发布内容

### Added

- **发布留痕连通性守卫（Issue #380 12/12 复盘，铁律 22）** — 新增 `validate:release-connectivity`（已入 `preflight`）：
  断言**发布标签 ↔ 版本号 ↔ CHANGELOG 段**的连通性（两条判据）——
  ① `vX.Y.Z` 标签所指向提交里的 `package.json.version` 必须等于 `X.Y.Z`；
  ② 每个 `vX.Y.Z` 标签在 `CHANGELOG.md` 必须有 `## [X.Y.Z]` 段。
  病灶为本轮实测出的**真缺陷**：`v1.11.0` 平台标签指向的提交版本竟是 `1.10.0`
  （Release 由 `main` 提前创建，而版本号落在未合并 PR 上 ⇒ 标签落到 1.10.0 树）。
  与 #353（断档编号）/ #357（已删机制）**同族**：文档/标签的「名」与真值之间无连通断言。
  设计要点：声明式**版本下限** `1.9.8`（非逐标签豁免，避免「自许可通道」）；
  `.cnb.yml` 增 `git fetch --tags`（防浅克隆无 tags ⇒ 守卫静默跳过 = 假绿）；12 例专测（含 4 例真实 CLI 变异自证）。
- **文档形态守卫新增「断档编号」判据（Issue #352 第十二刀，PR #378，merge commit `dd97559`）** — 与「已删机制」合并进同一守卫
  （`validate-removed-mechanisms.js`）+ 同一文档树，不新建文件：
  - **病灶**：#353 的原始形态（文档引用 `governance.js` 中**不存在**的治理规则编号）**无任何门禁可拦** ——
    实测向 `docs/USAGE.md` 非历史区注入一个已归并编号，轴 I / 已删机制守卫 / 体量闸门 **全绿**。
    根因：合法编号集合不是代码符号，天然落在轴 I 归属池之外（即 #359 元问题的自限）。
  - **数据单源**：`doc-drift-manifest.js` 新增 `RULE_REF_DERIVE`，合法编号集合**运行时从
    `governance.js` 头部声明行派生**（不手写第二份清单；派生源缺失即报红）。
  - **判据纯函数**：`doc-drift-scope.js` 新增 `checkDanglingRuleRefs`（模块内无仓库路径字面量）。
  - **双向口径**：非历史区命中报红 / 历史区命中缺显式标注同样报红；`P0-1` 类问题 ID 前缀由
    负向断言 `(?![-_])` 排除。
  - **自限（显式披露）**：只拦 `P/G/T + 数字` token（「第 16 条规则」之类自然语言指代不声称拦住）；
    只校验编号**是否存在**，不校验「用得对不对」（需人工评审）。

### Changed

- **方案 A：治理层服从注册层，内置工具一律放行直连（PR #375）** — 消除「注册层 / 治理层 / 文档层 / 校验脚本」四处口径互相矛盾的根因。
  - **根因**：启动即注册工具中有 6 个是「双路径」（既有直连注册名、又有网关名），「网关强制」规则曾一律强制走网关，但**既没从直连注册里摘掉，也没让文档停止教 AI 直连**；同一 skill 文件一处教直接调、另一处说「会被拦截」。AI 照着示例调 → 被拦 → 再搜 → 再试，盲试 30 余次、整轮零产出（#373 会话实测 71 次调用中 38 次报 `No active document`）。
  - ⚠️ **行为变更（用户可见）**：`governance.js` 的 `DIRECT_TO_GATEWAY` 由 13 键收敛为 **7 键**（全部为「网关专属」校对工具）；启动即注册的内置工具（数量以 `mcp-server.ts` 为准，实测 15）**一律放行直连**，不再被「网关强制」规则拦截。
  - **网关专属校对工具原样保留拦截**：`proofreadAccumulate` / `generateProofreadReport` / `enableTrackChanges` / `getTrackChangesStatus` / `replaceInParagraph` / `proofreadBasic` / `confirmBatchAiProofread`。
- **新增通道自检工具 `wps_whoami`（内置，可直接调用）** — 一次说清哪条通道断了，输出 `ready` / `channelReady` / `activeDocument` / `allowActions` / `blockedActions`；失败消息统一附「下一步：调 `wps_whoami` 自检」。用于终结「对同一失败调用反复重试」的盲试。
- **`wps_get_active_document` 失败恒报失败** — 不再把 launcher 心跳缓存包成 `success: true`（假成功诱导盲试）；缓存信息降级为**显式标注的「诊断线索·非成功」**。抛错 / 无缓存 / 有缓存三种形态均有行为测试守护（`active-document-honesty`，6 例）。
- **文档口径收敛** — `docs/SKILLS.md` 等 9 处消费方统一为「数量以 `mcp-server.ts` 为准（不写死数字）」；删除已变假的「网关强制」行；`docs/TROUBLESHOOTING.md` 新增「工具调用反复失败（`No active document`）排查」专章。
- **发布线诚实收口（Issue #380）** — ① CHANGELOG 补齐 v1.10.0 之后合并进 `main` 的第十二刀条目
  （此前 `[Unreleased]` 为空，该刀次变更未被记录）；② 发布产物构成口径按**发布提交快照**如实书写：
  `.gitignore` 已忽略 `dist/`，CI 校验步骤亦无 dist 构建 ⇒ 产物**不含** `wps-office-mcp/dist`。

### Fixed

- **`validate:toolcounts` 两处静默假绿** — 「内置工具」数原为**手写常量**（恒 12，真值 15）、COM Actions 原读**已迁移的旧数组**（恒 0，真值 257）。现三个数字（内置 / COM Actions / 注册工具）**全部派生自代码**（`mcp-server.ts` / `com-actions.ts`），脚本自身不再是漂移源。
- **补齐「注册层 ↔ 治理层 ↔ 文档层」交叉断言** — `validate-gateway-membership` 新增判据 G 双向（G-1「该放行的都放行」/ G-2「`DIRECT_TO_GATEWAY` 键无孤儿」）与判据 H（网关索引条目 ↔ 有执行者）；轴 I 新增第 9 语义键 `tool-count-source`（4 落点双向闭合）。两条判据均有真实 CLI 变异自证（由绿转红）。
