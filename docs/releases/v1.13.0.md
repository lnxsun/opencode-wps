# Release Notes — v1.13.0

- **发布日期**：2026-09-24
- **上一版本**：v1.12.0
- **语义化版本性质**：Minor（含**用户可见的行为变更**：NPC Team 流水线由 12 阶段扩为 **13 阶段**并新增 ⏸CP0 暂停点）
- **关联**：Issue #383 · PR #384（merge commit `74f37d6`）

## 一、本次发布内容

### Added

- **新增 1/13 深入分析阶段 + ⏸CP0 暂停点（Issue #383）** — NPC Team 流水线由 12 阶段扩为 **13 阶段**：
  1/13 深入分析（RES 主持 + PO 提问：问答定位 / 故障根因 / 头脑风暴 / 发散收敛，**可一轮一轮盘清**）
  → **⏸CP0 分析确认**（用户确认「盘清了、无遗漏」后才进拆解，成为第 5 个暂停点）。
  原 1/12「需求接收 + PO 澄清」合并进 1/13；需求覆盖度检查由「7/12 附加动作」提为 **8/13 独立环节**。
  ⚠️ **行为变更（用户可见）**：召唤话术的阶段号由 `1/12…12/12` 变为 `1/13…13/13`；
  1/13 未盘清时可回「补充：<意见>」再跑第 R+1 轮（**不前进**），盘清经 ⏸CP0 确认再转 2/13。
- **阶段总数单源化（Issue #383 C1/C2）** — `lib/npc-team-prompt-source.js` 的 `STAGE_COUNT` 成为唯一来源；
  `STAGE_PROTECTION` 环节保护表扩为 13 条（F1 环节覆盖实测 **13/13**）。

### Changed

- **NPC Team 提示词整体整改（Issue #383）** — 提示词正文 **159 行 → 85 行**（-46%），硬上限
  `LIMITS.promptLines` **190 → 90**（用户明确要求「严格控制上限为 90，只减不加至少持平」）。
  十二条相互矛盾之处逐条消解：
  - **A1/A2（豁免口径互斥）**：删除「简单需求可跳 2/3/6 非关键项」「3 可省略、4 简单跳过、7 按需裁剪」
    「ARCH 简单改动跳过」三套并存口径，统一为 **⏸CP 之外无豁免**（2/13~7/13 任何环节不得以「简单」为由跳过，
    只允许减「内容深度」）。
  - **A3（接力卡 PR 编号无兜底）**：铁律 12 增加「尚未有 PR 时写『尚无 PR（未到 5/13 开发棒）』」兜底口径。
  - **A4（留痕枚举 ↔ 流水线步数不对齐）**：留痕枚举随流水线收敛为 13 项，评审与修复表述为「评审-修复循环」一项。
  - **A5（⏸CP2.5 未在引导语点名）**：引导语收敛为「到 ⏸CP0/⏸CP1/⏸CP2/⏸CP2.5 输出暂停卡；到 ⏸CP3 输出【合并确认卡】」。
  - **A6（修复棒预判清零，因果倒置）**：清零判定与累计轮次统一由**复评棒**给出，前面各棒不预判。
  - **B1（铁律 16/17/18 内部条号跳号）**：理顺为 ①~⑥ / ④⑦⑨⑩ / ⑥⑪⑧⑫⑬⑭ 连续可读序列。
  - **B2（铁律 24 内嵌历史编号回潮）**：删除正文内嵌的 `~~Pxx~~` 历史编号（`validate:removed-mechanisms` 专治形态）。
  - **B3（交接话术硬编码 N+1/12）**：接力卡模板增加「若本步为 13/13 则写『流程结束，无下一步』」终止口径。
- **认知负担下降（量化）**：「禁止」51→24、「必须」51→25、「不得」39→25；7 张角色卡形状统一，
  最长角色卡 653→234 字（-64%）；最长铁律（铁律 24）1744→541 字（-69%）。
- **阶段总数三处硬编码派生（Issue #383 C1）** — 阶段号正则 `\/12`、`for (let i = 1; i <= 12; i++)`
  循环上界、段落标题字面量，一律派生自 `STAGE_COUNT`；新增**反向断言**（校验器可执行行内不得再出现 `/12` 字面量）。

### Fixed

- **7/13 测试回炉闭环 QA-D1** — 用户核心需求「1/13 可一轮一轮盘清」原先只写在文档散文里、
  提示词块内**零编码**（删掉该句门禁全绿）⇒ 把多轮口径写进提示词块（1/13 行 + ⏸CP0 卡）
  + 新增单源 `CAPABILITY_ASSERTIONS` 门禁（变异自证：删字面 → CLI `exit 1`）。
- **7/13 测试回炉闭环 QA-D2** — `SKILL.md` 的 `description`（人工维护、sync 不改写）里阶段号仍是旧的
  `6/12`/`9/12`/`10/12`/`5/12`，与正文迁移后的 13 阶段不一致 ⇒ 修值 + 新增单源 `checkDescStageNumbers` 门禁。
- **评审 CR2-1** — 11 处错误文案内手写旧阶段号 + 阶段数单源化反向断言（校验器错误文案内不得出现 `/12`）。
- **评审 CR5-1** — 暂停卡内容强校验（表驱动）+ 2 例专测。
- **评审 CR7-1** — 用例名与注释的阶段号统一为 13。

### Removed

- **三处手写阶段总数与两处手写段标题字面量（Issue #383「敢删」）** —
  `\/12` 正则、`i <= 12` 上界、「12 阶段」段锚点，以及三处 `prompt.match(/^【XX…\n([\s\S]*?)(?=\n【|$)/m)`
  段提取正则（该正则在 `m` 标志下 `$` 匹配行尾，惰性量词会立刻收尾于首行末 —— 实测段内容只捕获 1 行，
  导致角色卡片校验全部误报）；后者统一收敛为行式 `sectionOf` / `sectionBetween` 派生 helper。
