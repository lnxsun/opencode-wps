# Release Notes — v1.12.0

- **发布日期**：2026-09-24
- **上一版本**：v1.11.0
- **语义化版本性质**：Minor（含**用户可见的工具面变更**：校对工具改为直连注册，AI 可在工具列表中直接看见；`session_id` 参数被彻底移除）
- **关联**：Issue #382 · PR #385（merge commit `2603f6c`）

## 一、本次发布内容

### Changed

- **校对工具契约解耦：纯 TS 逻辑工具直连注册，取消「网关专属」（Issue #382 DECISION-1）** —
  按 **DECISION-1**「无 COM 方法可透传的纯 TS 逻辑工具一律直连注册」重写工具面，根治
  「AI 只看得见 15 个内置工具、校对工具须靠关键词搜索猜词才能发现且拿到残缺 schema」这一失真的
  **共同物理位置**。

  - **会话身份改由文档派生**：**彻底删除 `session_id`** —— 服务端 `deriveSessionKey(doc_info)`
    （`proofread-session.ts`，唯一定义者）按文档绝对路径派生 key；**无 `filePath` 即拒绝**
    （不回落 `fileName`，遵「不要下兜底」）。⚠️ **行为变更（用户可见）**：调用校对工具**不再传 `session_id`**；
    首次调用必须带 `doc_info`（含 `filePath`）。
  - **注册层**：删 `GATEWAY_ONLY_TOOLS` 黑名单；4 个纯 TS 工具（`wps_word_proofread_basic` /
    `wps_word_confirm_batch_ai_proofread` / `wps_word_proofread_accumulate` /
    `wps_word_generate_proofread_report`）补 `definition` 并进 `allTools`；`registerBuiltinTools()`
    **真实调用 `registerAll(allTools)`**（此前该调用**从未存在** —— 「直连注册」只是注释里的声明）。
    ⚠️ **行为变更（用户可见）**：工具面由此**多出 4 个直连工具**，AI 在工具列表中直接可见（含完整 schema）。
  - **治理层**：删 `DIRECT_TO_GATEWAY` 拦截表 + **「网关强制」规则整条**（+ 其 `GUIDE_MAP` 键）；
    G2 拦截消息回显真实 `method`（原读 `args.method` 落空 ⇒ 消息里是空串，诊断价值为 0）。
  - **「同名不得双通道」**：2 个报告工具的 COM_ACTIONS 条目整体删除（定义迁回与 handler 同居处）。
  - **让 schema 说真话**：`doc_info` 展开 4 子字段（全 `required`，含 `totalWords` —— 报告不再必然写
    「总字数: 0」）；`_processed_to_paragraph` 由 `required:false` 改 `true`（会硬拒的参数必须说必填）；
    `confirmBatchAiProofread` 由**空签到**改为必传 `ai_issue_count`，并由服务端与 Layer 1 实测条数
    **交叉核对**（报告新增「Layer 2 产出」披露节，申报 0 而 Layer1 命中 >0 的批次被显式标出）。
  - **删掉不生效的规则**：`proofreadBasic.text` 的 `maxLength=5000`（从未生效：网关 schema 转换丢
    `maxLength`、handler 无长度校验）三处措辞删除，只留「单批 200 段」；**不**把 `maxLength` 补进
    网关 schema（不给一条要删的规则做实现）。
  - **搜索可自纠**：`wps_office_search` 空结果给出「换同义词 / 传空 query 列全量 / 内置工具直接调」的提示。
  - **SKILL 与源码同口径**：删「7 个，直接调用」标题矛盾与「`batchStarted` 后必须走网关」条件句，
    改「直接调用 / 走网关 / 不存在」三栏清单；补 `getDocumentTextByRange` **超返裁定**
    （以 `returnedLength` 为准，`start_offset` 仅作 `baseOffset`）、长段 `findText` 取全量原文、
    `total_revisions` 传差值（记基线）。
  - **守卫重写**：`validate-gateway-membership.js` 判据 A~E（纯 TS 工具必直连注册 / 同名不得双通道 /
    索引条目必有执行者 / 不得再有网关专属黑名单 / schema 转换须搬运 required），482 → 274 行；
    10 例变异自证（逐判据注入反例由绿转红）。新增 `proofread-session-key-contract` 8 例回归。

### Fixed

- **直连调用绕过校对治理（CR10-1，实测复现）** — DECISION-1 后校对 4 个纯 TS 工具直连可调，而
  P1~P4 校对门禁此前**只写在 `wps_office_execute` 分支里** ⇒ 直连调用会**整体绕过**校对治理
  （批次推进 / 替换前置 / 进度真实性 / 覆盖全文门禁全部失守）。修复：新增 `normalizeToolCall`
  （唯一定义者），把「直连工具调用」归一成与网关调用**同一形状**，before/after 两钩子同口径消费。
  新增 `tests/governance-direct-call.test.js` 3 例（直连拦截 / 网关对照拦截 / 内置工具不误伤）。
- **`doc_info` 合并式更新导致总字数回归（CR1-2）** — 后续批次只带身份字段时整体覆盖会把首次的
  `totalWords` 抹成 `undefined`。改为合并式更新（只覆盖显式提供的字段）。
- **覆盖门禁可被下调 `totalParagraphs` 绕过（CR7-1）** — AI 谎报小值即可让 `processedTo >= totalParagraphs`
  提前成立（实测：1000 段文档报 250 即出报告）。改为**只允许上调**（降低一律忽略）。
- **报告「总字数: 0」残留（CR8-2）** — 未提供时不再静默填 0，改为写「未提供」（`totalParagraphs` 同口径）。
