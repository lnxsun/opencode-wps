## 一、本次发布内容

### Added

- **判据⑨：历史产物的处置完整性（PR #421，Issue #419）** —— 1.14.1~1.14.6 六个历史 tarball
  （约 189MB）的处置此前只是 Issue 里的一句话，**无断言**。而判据⑥ 的判据面**恰好就是**这六个版本
  （`RELEASE_ARTIFACT_FLOOR` = 产物惯例建立点）⇒ 「删历史产物」= 掏空判据面本身。
  本判据把处置结论落成**可执行断言**：
  ① **曾入库**：`>= 未决处置下限` 的产物必须有过入库记录（`git log --diff-filter=A`）；
  ② **接口自洽**：`未决处置下限 >= 产物下限`（否则待处置区间被静默归零）；
  ③ **决策有落点**：`decisionRefs` 须为非空数组且每条形如 `#<编号>`（空壳登记不受理）。
  - 单源：`ARTIFACT_FLOOR_DECISION_REFS`（处置决策登记）+ `ARTIFACT_FLOOR_UNDECIDED_BELOW`（未决处置下限）。
  - **判据⑨ 只断言判据⑥ 结构上做不到的部分**（反重复）：删产物这一后果由判据⑥ 承担
    （实测：删除冻结下限以上产物 ⇒ 判据⑥ 报「待发布树内找不到产物」），判据⑨ 不报第二份。

### Fixed

- **判据⑥ 读口径：`refs/heads/main` → `HEAD`（待发布树）（PR #421，CR419-1）** ——
  被断言的对象是 **HEAD 的树**（判据⑦ 跑 `git archive HEAD`、发布产物也由 HEAD 生成），
  而 CI 在 **PR 分支**上跑 `preflight`（`main` 尚未含本次改动）⇒ 二者可背离：
  - 实测（feature 分支上删产物）：`git rm opencode-wps-v1.14.7.tar.gz && git commit`
    ⇒ 原口径读 `main`（未删）⇒ `EXIT=0`（**假绿**：真实产物已缺文件）。
  - 修法：统一到 `HEAD` ⇒ `HEAD ↔ archive ↔ 产物` 三者同源，**且该判据可在 PR 合并前跑**。
- **判据⑨ 判据面补 `>= floor`（PR #421，CR419-2）** —— 原只判 `>= 未决下限`；当未决下限被改到
  低于产物下限时，`v1.14.0`（产物惯例建立**之前**）被拉进判据面 ⇒ 对合法历史**假红**「从未入库」。
- **判据⑨ 决策登记收为 `^#\d+$`（PR #421，CR419-5）** —— 原只查「非空数组」；
  实测 `['x']` / `['']` 原样放行 ⇒ 「决策有落点」断言**空心化**
  （与 `lib/ratchet.js` 的「空壳留痕不受理」同口径收口）。
- **判据⑨ 未决下限「抬高」对偶断言（PR #421，CR419-11）** —— 判据⑨ 内部的
  `② 未决下限 >= 产物下限` **只拦下调**；把未决下限**上调**（1.14.7 → 99.0.0）⇒ 全部历史产物
  落入「待处置区间」⇒ 判据⑨ 判据面为空、守卫仍 `EXIT=0`（**零信号**）。
  本 PR 自己批判的「方案 B 豁免口袋」**同构形态**（口袋从「标签清单」换成「一条可上调的下限」）。
  修法：判据面非空时，未决下限不得高于最高的在树产物版本（与判据⓪/④ 同口径）。
- **判据⑥「不可判定」用例断言无主修正（PR #421，CR419-10）** —— 该用例在判据⑥ 口径改为
  `HEAD` 后**已不再命中判据⑥**（夹具判据面为 0），其 `assert.match(out, /无法判定/)` 实由
  **判据③** 满足（用例名说判据⑥、断言由判据③ 满足 = 断言无主）。
  改为直接构造判据⑥ 的不可判定态 + 断言其**独有文案**。
- **轴 I 语义键 `artifact-floor-integrity` 登记（PR #421，CR419-4）** —— 本轮实测出的**归属侧盲区**：
  `scripts/lib/release-connectivity-manifest.js` 此前仅**间接**命中 `guard-source-budget` 锚点，
  ⇒ 该文件内新增的**同义实现**（如「历史版本豁免清单」）在轴 I 归属侧**零信号**。
  这正是「判据⑥ 加豁免清单」这一候选方案在本仓被否决的**实测原因**（它就是个静默放宽口袋）。
  登记后该语义的落点集合双向闭合（自证：把豁免清单写到树内任一文件 ⇒ 轴 I 报「漏登记落点」）。

- **历史巨型产物（1.14.1~1.14.6，约 189MB）本轮不清理** —— 与判据⑥ 相斥（实测删除会使判据⑥
  报红 **6 条**：1.14.1~1.14.6；Issue 原文写「7 条」，实测按 6 条记账）。
  ⇒ 本 Issue 的处置结论 = **保留、不动**，并把该结论固化为判据⑨（不再是 Issue 里的一句话）。
  克隆成本不变，属**已知既有债**；将来若要清理，须显式修改 `ARTIFACT_FLOOR_DECISION_REFS` 与
  `ARTIFACT_FLOOR_UNDECIDED_BELOW`（必产生 diff ⇒ 可评审）。
- **判据⑨ 残余自限**：断言的是**存在性**（曾入库），**不**断言产物内容/校验和 —— 属人工评审面。
  「曾入库」口径用 `git log HEAD`（非全 ref）：产物只在**未合并**分支上出现过不算「已入库」。
- **真实 WPS COM 端到端**：本环境无 WPS，未闭环（与本仓既有「条件项」披露一致）。本轮改动为
  **守卫层**，不经 COM 通道，该条件项不影响本次发布内容。

## 四、合并期发现并收敛的冲突（如实记账）
