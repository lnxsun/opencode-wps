## 一、本次发布内容

### Fixed

- **判据⑥：发布产物 ↔ 版本号连通（PR #416，Issue #399）** — 判据 ⓪~⑤ 全部只看标签 / CHANGELOG /
  Release Notes，**无任何断言覆盖产物（tarball）本身** ⇒「产物没做 / 名字写错 / 没进发布分支」
  可长期静默通过。逐版本 `tar -tzf` 核对才发现产物链**逐版本翻倍**（1.14.1 2.9M → 1.14.6 93M，
  内含上一版 tarball）—— 正是「无断言 ⇒ 无症状」。修法：新增判据⑥ —— 每个 ≥ 下限
  （`RELEASE_ARTIFACT_FLOOR` = 1.14.1）的发布标签，其**发布分支树**内必须存在与版本号同名的产物
  `opencode-wps-v<X.Y.Z>.tar.gz`。命名口径单源 `ARTIFACT_NAME_PATTERN` + 唯一构造函数
  `artifactName(v)`；纯函数 `checkArtifactConnectivity` + CLI 编排。
  ⚠️ **查发布分支树而非标签提交**：本仓产物惯例为「四要素提交 → 产物提交」两段
  （实测 `v1.14.6` 标签指向 `967ee3a`，tarball 在其后的 `71f1c6c`）⇒ 对标签提交断言会系统性假红。
- **E1 变异探针规模改为派生** — 两个 E1 变异探针把规模**写死为 500 行**；基线抬到 `9509` 后
  5% 余量 = **501** 行 ⇒ 500 行落入余量内 ⇒ 探针不再越上限 ⇒ 断言**静默假绿**。
  修法：新增 `excessOverLimit()` —— 现场从守卫源码结构化解析基线并按余量派生探针规模（`余量 + 20`）。
- **E1 记账链三方对账** — 对本 PR 自证做独立复验，实测复现三条真缺陷：
  ① 🔴 **基线低估**（`E1_BASELINES.guardSourceLines = 9509` = 本 PR 首个提交当刻值，其后再落 6 提交
  ⇒ 实测 **9546**）；② 🔴 **初值幽灵**（`E1_RATCHET_INITIAL.guardSourceLines = 5379`，落后现基线
  **4167 行 / 7 个版本**；改成 `1`/`99999` 跑守卫**恒为全绿**，零信号）；③ 🔴 **留痕链脱钩**
  （留痕末条 `.to` 与实测/基线脱钩 —— 「改了不留痕 / 留痕不改值」在 `E1_BASELINES` 自身上复发）。
  **必答质疑**：「值与实测不一致，不是本来就被守卫拦吗？」——**不是**。E1 上限 = `ceil(基线/0.95)`，
  余量 5%（构造保证）；基线落后实测 37 行时落在余量内 ⇒ 不报红 ⇒ 属「余量内作弊通道」在 E1 自身上的实例。
  修法：基线 / 留痕末条 `.to` / 初值**三方按 `guard-sources.js` 机械枚举当场对账**回写实测值；
  新增「**初值陈旧可见披露**」运行时判据（诚实边界：只对**已登记留痕**的维度有信息）。
- **E1 棘轮自指闭合（CP3 前复验）** — 复验实测发现：光改基线（探针 A）能被拦，但「基线 + 留痕同步」（B）/
  「三步全同步」（C）/「实测换成同文件副本」（D）三者**均零信号**放行。根因：
  `e1RatchetBaseline(dim) = log.at(-1).to` —— **比较对象与被判对象是同一处文本**。
  修法：新增三条**独立 CLI 判据**（进 `validate-semantic-anchor-scope.js`，不只在测试层）：
  ① `E1_RATCHET_ANCHOR`（与留痕**互不派生**的锚定来源 —— 漏改任一处即报红）；
  ② 「基线 = 当场实测」对账（实测由 `guard-sources.js` 现场派生，与 `E1_BASELINES` 无写关系；
  高于/低于实测两方向各有诊断）；③ 实测来源唯一性（防「实测换成同文件副本」⇒ 对账退化为自指）。

## 三、条件项与既有债（未闭环，如实披露）

- **真实 WPS COM 端到端**：本环境无 WPS，未闭环（与本仓既有「条件项」披露一致，不假装已闭环）。
  本轮改动为**守卫/记账层**，不经 COM 通道，该条件项不影响本次发布内容。
- **判据⑥ 残余自限**：只断言「产物**存在**且与版本号**同名**」（可见形态）—— **不**校验内容 /
  体积 / 校验和；「产物存在但内容错误 / 体积异常增长」属人工评审（**产物翻倍**的体积问题已单独
  登记为 Issue #417）。判据⑥ 依赖**本地可见的发布分支引用**；分支未 fetch 时如实报红（不假装通过）。
- **E1 记账链残余自限**：第四轮修的是「**记账链**」三方对账，**不**改 E1 的 1.05 余量设计本身 ——
  「基线可落后实测最多 5%」这一结构性余量**仍在**（它是有意的施工余量；本轮把「值与实测的当场一致性」
  另立为独立断言来补它）。「初值陈旧披露」只对**已登记留痕**的维度有信息，对未登记留痕的维度
  **不声称**能判断其初值是否陈旧。锚定只覆盖 `guardSourceLines` 维；其余 8 维同改同过**仍成立**。
- **对照实验（铁律 21）**：合并前本地预检曾见 `tests/validate-release-connectivity.test.js`
  报红一条（`⑤ 历史边界不早于版本下限`）—— 经对照实验确认为**环境性失败**
  （本地克隆未 `fetch --tags`，`v1.13.0` 不存在；`git fetch --tags` 后 EXIT=0），
  **与本次改动无关**，不记为阻塞。
