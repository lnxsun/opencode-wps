## 一、本次发布内容

### Fixed

- **发布留痕守卫判据⑤ 修三处实测真缺陷 + 加历史边界（PR #414，Issue #399）** —
  判据⑤「发布提交 message 声称 ⊆ 其 CHANGELOG diff 落地」经**独立复验**，实测发现三处缺陷
  （1 假阴性 + 2 假阳性，全部实测复现，非推断）：

  - 🔴 **假阴性 · 判据对自身头号反例放行**：判据⑤ 的头号宣称反例 `77d9e76`（v1.14.2 发布提交
    message 称 CHANGELOG 含 `G3` 修复，而 diff 新增行 0 处提及）。原实现的「声称集合」只收
    `#<数字>`，而该行真正的见证词 `G3` 是**功能代号**（非 `#` 编号）⇒ 永不进入声称集合；
    该行唯一的编号 `#400` 恰在同提交 diff（另一条目）中 ⇒ 子集断言误过 ⇒ **放行（假阴性）**。
    修法：见证词口径扩为编号 `#<数字>` **∪** 功能代号 `G/P/T<数字>`（新增单源
    `RELEASE_COMMIT_WITNESS_PATTERN`）。实测 `77d9e76` 现报红 `G3`。
  - 🟡 **假阳性 · 两端口径不对称**：扩口径后声称侧收「编号 ∪ 功能代号」，而真值侧
    （`changelogAddedRefsOf`）只收编号 ⇒ 声称 `P2` 而 diff 真含 `P2` 被误报「0 处提及」
    （实测反例 `49bb613`）。修法：真值侧改用**同一**见证词单源（两端口径同源）。
  - 🟡 **假阳性 · 提交标题被误认声称**：声称行判定把**提交标题**（工作描述）计入，其 Issue/PR
    追溯号被当成「声称落地的条目」（实测反例 `b7d7757`）。修法：排除首行
    （实测真实声称 27 条在 body / 6 条在 subject）。
  - **配套：判据⑤ 历史边界（声明式、可审计）**：`77d9e76` 是不可变历史提交（缺陷已由 PR #411
    补录闭环），不设边界则永久报红 ⇒ 门禁不可用。故新增 `RELEASE_COMMIT_CLAIM_SINCE`
    （**一条均匀时间边界**，非白名单口袋）+ `RELEASE_COMMIT_CLAIM_KNOWN_WITNESSES`
    （边界内已登记反例，可审计）；边界提交在任意 `--root` 不存在时**如实退回**未收紧范围
    （多判，不静默空跑）。
  - **R1 评审（契约唯一）**：删声称侧冗余编号匹配 —— `witnessPattern` 已 ⊇ `refNumberPattern`，
    同时两次 match 属「同一语义两处写」，只保留单一 `witnessPattern`。

## 三、条件项与既有债（未闭环，如实披露）

- **真实 WPS COM 端到端**：本环境无 WPS，未闭环（与本仓既有「条件项」披露一致，不假装已闭环）。
  本轮改动为**守卫/发布留痕层**，不经 COM 通道，该条件项不影响本次发布内容。
- **判据⑤ 残余自限**：只认「**同一行内** CHANGELOG 关键词 + 写入动词 + 见证词」的可见形态 ——
  跨行声称、**无见证词**的自然语言声称（「修了校对抽风」）**不声称**拦住；
  body 内「上下文提及」无法与「声称」自动区分（仍不声称拦住）；只校验声称的见证词是否真在
  diff 出现，**不校验** diff 条目的语义正确性（属人工评审）。
- **对照实验（铁律 21）**：合并前本地预检曾见 `tests/validate-release-connectivity.test.js`
  报红一条（`⑤ 历史边界不早于版本下限`）—— 经对照实验确认为**环境性失败**
  （本地克隆未 `fetch --tags`，`v1.13.0` 不存在；fetch 后 EXIT=0），**与本次改动无关**，不记为阻塞。
