- **发布日期**：2026-09-28
- **上一版本**：v1.14.1

- **关联**：Issue #395 · PR #404（merge commit `33a9006`）· PR #406（merge commit `0d18695`）· PR #403（merge commit `d5b4e65`）
- **主题**：Issue #395「校对抽风」收口 —— G3 跨 app 恒拦修复 + 工具结果信封契约单源 + 守卫层扩面

## 一、本次发布内容

### Fixed

- **G3「读前必写」对 Excel / PPT 恒拦（PR #404，Issue #399）** — `appReadState` 读取侧只认
  `activeDocRead`，而 Excel/PPT 置位侧写 `activeWorkbookRead` / `activePresentationRead`
  ⇒ 永远读到 `false`（字段名不一致）；叠加 `getAppType` 只认 COM 短名前缀、注册名归一后掉进
  `'word'` 兜底 ⇒ 字段名即使修好 PPT 仍恒拦。现把字段名收敛为 `appReadStateSlot()` **单源构造**
  （读取/写入共用），app 归属改为按**应用段**判定 + COM 语义词表兜底（两通道归一后同形）。

### Changed

- **工具结果「信封契约」收敛为单源（PR #406，Issue #401 W-2）** — 治理层 `enableTrackChanges` /
  `generateProofreadReport` 两处消费点原读 `output.success`，而该键在 `mcp-server.ts` 投影
  `{ content, isError }` 中**已被剥离** ⇒ 读到的恒为 `undefined`。现改读投影后唯一存活的
  `output.isError`；after 钩子入口早退（遮蔽失败分支）亦随之拆除；死标记 `'success:false'` 删除。

### Added

- **工具结果信封契约独立守卫（PR #406）** — 新增 `scripts/validate-tool-result-payload.js`
  并纳入 `npm run preflight`：断言「治理层读的信封顶层键 ⊆ 投影后真实存在的键」，
  且禁止把**字段名**写进兜底文案。语义键 `tool-result-payload` 已登记进轴 I 清单。
- **P2 不变量行为守卫 + 校对整链报告环（PR #405 / PR #403）** — 已随 v1.14.1 发布；
  本次发布说明引用其口径，详见 `docs/releases/v1.14.1.md`。
