## 一、本次发布内容

### Fixed

- **发布产物 tarball 逐版本翻倍（PR #418，Issue #417）** —— `git archive` 打包**全部 git 跟踪文件**，
  而历史产物 `opencode-wps-v<X.Y.Z>.tar.gz` 自 v1.14.1 起均被提交 ⇒ 每个新产物**递归包含全部历史产物**
  ⇒ 体积逐版本约翻倍（实测 1.14.1 2.9M → 1.14.6 93M → 1.14.7 186M，`tar -tzf` 各含 1~7 个 tarball）。
  修法：`.gitattributes` 新增 `opencode-wps-v*.tar.gz export-ignore`（排除口径由
  `ARTIFACT_EXPORT_IGNORE_PATTERN` 单一来源声明）。
  **实测**：archive 条目 370 → 362，内含产物 8 → **0**，gzip 后 **389,341,079 B → 1,634,373 B**（−99.6%）。
- **新增判据⑦：发布产物的打包口径 / 体积连通（PR #418）** —— 判据⑥ 只断言产物「存在性/命名」
  （可见形态），**内容/体积**明确写在其自限内，正是这条自限让「产物逐版本翻倍」长期静默通过。
  判据⑦ 三条断言：
  ① **产物不入产物**：发布产物内不得出现产物命名形态的条目 —— 断言钉在 `git archive` **输出**上
     （**不**用 `git check-attr` 代替：实测 `export-ignore` 是 attribute，`check-attr` 在索引/工作树
     已 set 而 `git archive HEAD` 读的是 **HEAD 树**的 attribute ⇒「check-attr 绿 + archive 仍含产物」
     二者可同时为真，属**假绿形态**）；
  ② **排除口径同源**：`.gitattributes` 的 `export-ignore` 行必须**等于**单源 pattern，且该 pattern
     必须能匹配唯一构造函数 `artifactName()` 的产物名；
  ③ **体积上界**：archive 的 gzip 后字节 ≤ 上界（**派生量** = 基线 × 唯一自由倍率）。

### 判据⑦ 的自由参数收敛（设计说明）

判据⑦ 经评审-修复循环 **10 轮**打磨，**自由参数从 4 个收敛为 2 个绝对量**：

| 参数 | 角色 |
|---|---|
| `ARTIFACT_SIZE_BASELINE_BYTES` | 实测基线（1,634,373 B）—— 唯一实测量 |
| `ARTIFACT_SIZE_TOLERANCE_RATIO` | 余量倍率（16）—— 唯一自由倍率，上界由它**派生** |
| `ARTIFACT_SIZE_LIMIT_BYTES` | **派生量**（`= 基线 × 倍率`，恒等式由构造保证） |
| `ARTIFACT_SIZE_REF_BYTES` | 漂移对账的独立参照（防判据面自排除） |
| `ARTIFACT_SIZE_BASELINE_MAX_DRIFT` | 基线相对当场实测的漂移上限（4×） |
| `ARTIFACT_SIZE_RATIO_CEILING` | 倍率的绝对上限（32） |

**为什么收敛**：每加一个「防护参数」就多一处**可被同步放大**的文本 ——
实测「上界 + 基线两处同步」「倍率 + 基线 + 上界三处同步」均曾 `EXIT=0` 零信号
（与 Issue #416 的 E1 记账链同构）。收敛后「只改上界」在语法上不可能；
「同步放大」由「倍率绝对上限」与「基线 ↔ 当场实测对账」两条独立断言拦住。

## 三、条件项与既有债（未闭环，如实披露）

- **历史巨型产物（1.14.1~1.14.6，约 189MB）未清理** —— 与判据⑥ 相斥（删除会使判据⑥ 报红 7 条，
  修复打断门禁）⇒ 已拆**独立 Issue #419**（含方案评估与合规路径）。
- **判据⑦ 残余自限**：
  - `--worktree-attributes`：判据用 `git archive HEAD` 默认语义（读 HEAD 树 attribute）；
    若构建方改用该选项，「工作树改坏 pattern」可使真实产物重新含产物而判据仍判定通过
    （实测 0 → 1）。本仓发布命令与 CI **均未**使用该选项，使用该选项时须人工核对。
  - 「五处齐改」：不声称拦住「有权限且有决心**同时**放宽倍率 + 基线 + 倍率上限 + 漂移上限（+参照）」
    的维护者动作 —— 与 `lib/ratchet.js` 的棘轮判据自限同口径。第 5 轮已实测：
    任一/任二/任三单点或部分同步**均报红**。
  - 产物**内容正确性**（该含哪些文件、清单语义）仍属人工评审；上界为宽松阈值，不卡精确值。
- **真实 WPS COM 端到端**：本环境无 WPS，未闭环（与本仓既有「条件项」披露一致）。本轮改动为
  **守卫/打包层**，不经 COM 通道，该条件项不影响本次发布内容。
