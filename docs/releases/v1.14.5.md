## 一、本次发布内容

### Fixed

- **信封守卫判据① 闭合「间接读」盲区（PR #412，Issue #401）** — `validate-tool-result-payload`
  判据① 原只按**成员访问**形态（`.key`）判「消费点读过某信封键」，因此它拦得住 `output.success`，
  却拦不住把键名**先绑到标识符**再用计算成员读取的**同一行为**。实测（真实注入 `governance.js`）：

  ```js
  // 注入：(function(){const k='success';return output && output[k] !== false && !failedByText})()
  node scripts/validate-tool-result-payload.js  →  EXIT=0   ← 守卫全绿（假绿）
  ```

  ⇒ Issue #401 的**本源 bug**（读投影后不存在的键）**换个写法就绕过了守卫**，与要治的缺陷**同族**。
- **判据① 新增「间接读」面**：先收集 `const/let/var <id> = '<字段名>'` 的**别名绑定**，
  再拦 `obj[<id>]` 形式的读取；并按 `(别名, 键名)` **去重**，避免同一别名重复报红。
- **防误报的关键约束**：**只登记「绑定值 = 字段名」的别名** —— 与信封无关的同名局部变量
  （如 `for (var k=0; ...)` 循环计数器）绑定值不是字符串键名，**不会被判为别名**（M10 专测钉死）。
- **字段名单源不变（R5 口径保持）**：别名候选仍由 `types/tools.ts` 的 `ToolCallResult` /
  `CallToolResponse` **源码派生**，经 `checkEnvelopeKeyUsage` 第 3 参传入 —— 守卫内**无第二份手写清单**。
- **自限措辞与实测对齐**：原自限①「间接读不在覆盖内」按实测改为「**已闭合**」，并如实收窄**残留**自限
  （经**再赋值 / 函数参数 / 对象属性**间接传递者**不声称**拦住 —— 本仓 `grep` 无该形态）。
- **轴 I E1 棘轮同步回写 + 留痕**：本 PR 与 `main`（`#413` 判据⑤）**合并**后各维按**合并态实测**回写
  （`guardCodeLines` 1371 / `guardSourceLines` 9213）；E1 留痕按**时间序**拼接
  （`#399 11/13` → `#399 13/13` → `#401 13/13 复盘`），`checkRatchetLogChronology` 链条连续。
