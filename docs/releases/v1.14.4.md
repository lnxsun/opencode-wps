## 一、本次发布内容

### Added

- **发布提交 message「假留痕」守卫（判据⑤，PR #413，Issue #399）** — `validate:release-connectivity`
  原判据①②④ 均**只看真值侧**（标签 / 段存在 / 段内容），对「发布提交 **message 声称**」这一侧
  无任何断言 ⇒ message 与 diff 各说各话可长期存在。实测反例：v1.14.2 发布提交 `77d9e76` 的 message
  声称「CHANGELOG：新增 `## [1.14.2]` 段（G3 跨 app 恒拦修复…）」，而其 CHANGELOG diff 新增行中
  `#399`/`#404`/`G3` 命中 **0** 处（`git show 77d9e76 -- CHANGELOG.md | grep -cE '^\+.*(#399|#404|G3)'`
  → `0`）。判据⑤ `checkReleaseCommitClaim` 断言「message 声称落地的引用集合 ⊆ 该提交 CHANGELOG
  diff 新增行引用集合」。
- **声称侧口径**：message 行内「CHANGELOG 关键词 + 写入动词」**同行共现**才算一条声称行
  （初版只认关键词 ⇒ 实测 6 条合法提交假红 `39cc33f`/`e32d250`/`7e321de`/`46b7170`/`e2f4a54`/`d065101`）；
  无声称行即不在判据面（不对普通提交泛化误报）。
- **判据面**：取**版本下限 tag 的提交范围**（与判据④ 同源），条数上限降级为兜底
  （不用条数窗口 —— 窗口会随主线提交密度静默收窄，同族 Issue #352 第十一刀）。
- **候选集**：加 `--no-merges`（merge 的 `git show` 给 combined diff，与「相对主线实际新增行」
  不等价 ⇒ 系统性假红）。
- **契约唯一**：编号口径复用既有 `REF_NUMBER_PATTERN`；初版自建的
  `RELEASE_COMMIT_REF_NUMBER_PATTERN` 与 R10 残留的内联 `/#(\d+)/` 均已删除。
